# Mäusebau – Arbeitsregeln für Claude Code

Browser-Spiel (3D-Koop-Stealth, offline-fähige PWA). **Quelle der Wahrheit:**
1. `docs/superpowers/specs/2026-09-21-phase0-phase1-design.md` (freigegebenes Design, Meilensteine M0–M20)
2. `docs/decisions.md` (Abweichungen von der Spec + Messergebnisse)
3. `Game_Design_Mouse.md` (ursprüngliche Spec – **Abschnitt 10 überstimmt ältere Abschnitte**)

Sprache: mit dem Nutzer und in UI-Texten **Deutsch**.

## Befehle
- `npm run dev` – Desktop-Entwicklung (kein Service Worker)
- `npm run verify` – Lint + Typecheck + Tests + Pages-Build + check-dist + E2E-Tor (vor jedem „fertig")
- `npm run phone` + `adb reverse tcp:4173 tcp:4173` – Handy-Loop ohne Service-Worker-Cache → am Handy `http://localhost:4173/?expect=<Build-ID>`
- `npm run e2e:smoke` – das E2E-Tor: alle Specs **ohne** Tag `@local` (Offline-Smoke, Zwei-Tab-Labor über BroadcastChannel); läuft in `verify` und in der CI vor jedem Deploy
- `npm run e2e:local` – nur die `@local`-Specs (Tooling-Spike, echter WebRTC-Ablauf, Selbsttest); nur auf dem Entwicklungsrechner, nie in der CI
- `npm run e2e` – alle Playwright-Tests (Tor + `@local`). Direktaufruf in PowerShell mit Anführungszeichen: `npx playwright test --grep '@local'` – sonst deutet die Shell `@local` als Splatting
- `npm run e2e:fakecam` / `npm run e2e:fakecam-foreign` – die beiden Fake-Kamera-Smokes einzeln (Projekte `chromium-fakecam` / `chromium-fakecam-foreign`, beide im Tor). `tests/e2e/globalSetup.ts` schreibt die beiden `.y4m`-Dateien einmal je Lauf nach `test-results/fakecam/` – nie committen
- `npm run core:bench` – Messlauf des Kerns (µs je `step()` und `hashState()`); die Zahlen gehören nach `docs/decisions.md`, nie in eine Test-Zusicherung
- `npm run core:rebaseline` – schreibt `tests/fixtures/core/golden.json` neu und druckt alt → neu; nur zusammen mit einer neuen `Rebaseline:`-Zeile in `docs/decisions.md` committen
- `npm run check-dist` – prüft den vorhandenen `dist/`-Ordner (Offline-Fallen, Schichtgrenzen im Bundle, Precache, Budgets)
- `npm run build:pages` – Pflicht vor `check-dist` **und vor jedem Playwright-Lauf**: beide prüfen immer den vorhandenen `dist/`-Ordner, nie den Quelltext
- `Get-NetTCPConnection -LocalPort 4173` – nach Playwright-/Preview-Läufen prüfen: lokal wird ein laufender Preview **wiederverwendet** (`reuseExistingServer`). Stammt er aus `npm run phone`/`phone:pwa`, hat er die falsche `base` und die Tests scheitern an 404-/MIME-Fehlern → diesen Prozess vorher beenden.

## Harte Regeln
- **Schichten:** `src/core` kennt weder DOM noch Babylon noch andere Schichten. `src/net` und `src/lab` kennen weder `src/render` noch Babylon. `src/render` kennt weder `src/net` noch `src/lab` (Babylon ist dort erlaubt – **außer** in `src/render/view2d/**`, dem Babylon-freien Entwicklerweg); `src/modes` orchestriert Kern, Eingabe und Plattform, kennt aber weder `src/render` noch Babylon, `src/net` und `src/lab` (die Richtung ist **render → modes**); `src/platform` ist die unterste Browser-Schicht und kennt weder `src/render`, `src/modes`, `src/net`, `src/lab` noch Babylon; `src/input` kennt **nur** `src/core`. `src/ui` bekommt die Netz-/Labor-Sperre bewusst **nicht** – `strings.ts` importiert einen Typ aus `src/net/failureCodes`, und `no-restricted-imports` kennt kein `allowTypeImports`. ESLint erzwingt das, auch für dynamische `import()` – Regeln nie lockern, sondern den Code umbauen.
- **Babylon nur so:** genau **ein** Paket (`@babylonjs/core`, exakt gepinnt), und `src/render/babylonRegistry.ts` ist die **einzige** Datei mit Nebenwirkungs-Importen (17 Zeilen, `BABYLON_SIDE_EFFECT_IMPORTS`). Jede andere Datei importiert Bindungen aus tiefen Pfaden. Verboten (ESLint, als **exakte** `paths` – ein `group`-Muster trifft gitignore-artig auch jeden erlaubten tiefen Pfad): `@babylonjs/core`, `@babylonjs/core/pure`, `@babylonjs/core/Engines/engine` (der Sammel-Import holt KTX2/Basis ins Bundle), dazu weiter `Legacy/**` und jedes `import * as`. Babylon ist **nur** in `src/render/**` erlaubt – außerhalb statisch wie dynamisch gesperrt, auch in `src/platform`, `src/ui` und `src/audio` (beide hängen am **eifrigen** Einstiegs-Chunk). `ALLOWED_BABYLON_URLS` in `scripts/lib/distChecks.mjs` enthält **eine** Babylon-Doku-URL (ein `console.warn` in `Misc/devTools.js`) – jede weitere ist ein Befund. Ein fehlender Nebenwirkungs-Import ist **weder Build- noch Typfehler**, sondern ein Wurf zur Laufzeit oder eine schwarze Szene: wer einen neuen Babylon-Aufruf ergänzt, sieht sich das Bild an. Messwerte: `docs/decisions.md`, „M5 – Graybox am Desktop".
- **Level-JSON ist die einzige Quelle:** Geometrie, Verstecke, Beuteplätze und Wegpunkte stehen in `src/data/levels/*.json`, nie im Code. `validateLevel` (12 Regeln, `src/core/world/validateLevel.ts`) ist der Beweis; ein Layout-Fehler wird in der **JSON** korrigiert, nie im Test. Die Kollider-Reihenfolge ist Vertrag: Wände → Regale → Kisten → Pflanzen → Mauseloch-Stopfen, neue Arten werden **angehängt** (die `id` ist der Tiebreak jeder Abfrage). Kollider-, Wegpunkt- und Kantenzahl von `feinkost.json` sind in Vitest gepinnt; `feinkost` hat bewusst **keinen** gepinnten Zustandshash.
- **Reine Module in `src/lab`:** `labTypes.ts`, `labEvents.ts`, `report.ts`, `pairing.ts` und `lockTest.ts` kennen kein DOM und keine Browser-API – alles Messbare ist so mit Vitest im Node-Umfeld prüfbar. `src/platform` importiert nie `src/lab`; `wakeLock.ts` meldet seinen Zustand deshalb über einen Rückruf.
- **Hook-Graph:** alles, was `src/lab/labHook.ts`, `src/render/view2d/hook.ts`, `src/render/view2d/draw.ts` oder `src/modes/hook.ts` exportiert, darf `report.ts`, `labSession.ts`, `net/environment.ts`, `platform/buildInfo.ts` und jede `.css` weder direkt noch mittelbar erreichen – sonst bricht `tsc -p tsconfig.node.json` an `__BUILD_ID__` bzw. TS2882.
- **Hook-Test:** deshalb wohnen `ScanBackend`/`TrackState`/`QrFacts` im importfreien Leaf-Modul `src/lab/labTypes.ts`, sind `src/render/view2d/hook.ts` und `src/modes/hook.ts` **ganz** importfrei (ihre `MbStats` bestehen nur aus Zahlen und nackten Zeichenketten; die Build-ID wird von `src/main.ts` **injiziert**), und CSS wird nur aus `src/lab/labMain.ts` bzw. `src/ui/shell.css` geladen. `tests/node/labHook-graph.test.ts` bewacht **vier** Einstiege samt der Gegenprobe über `src/main.ts` (die auch zeigt, dass der Wächter `import()` sieht); repariert wird im **Modul**, nie in `tsconfig.node.json`.
- **`qr-scanner` nur über die öffentliche API:** nie eine `QrScanner`-Instanz (ihr `stop`/`destroy`/`pause` beendet unseren Kamera-Stream, ihr Konstruktor hängt `visibilitychange` ein) und nie ein Unterstrich-Mitglied. Erlaubt sind genau `QrScanner.createQrEngine()` (einmal je Seitenaufruf) und `QrScanner.scanImage(source, { qrEngine, returnDetailedScanResult: true })` – ohne `scanRegion`.
- **Determinismus in `src/core`:** nur Integer-Ticks (30 Hz), Seeded-PRNG aus dem State, Trig nur über `src/core/math`. Verboten: `Math.random|sin|cos|tan|atan2|pow|exp|log*|hypot|cbrt…`, `Date`, `performance`, Timer. Iteration nur über Arrays; Sortier-Gleichstände per ID auflösen.
- **Keine Reflexion im Kern:** kein `Object.keys/values/entries/assign/fromEntries`, kein `JSON.parse/stringify`, kein `for…in`, kein `structuredClone`. ESLint sperrt die **direkten** Formen (`Object.*`, `JSON.*`, `for…in`, `**`, `new Date`), der Typecheck `structuredClone` (`tsconfig.core.json`: `lib ES2022`, `types: []`). Nicht maschinell erfassbar und deshalb **Review-Regeln** (gemessen, siehe `docs/decisions.md`): Aliasse (`const M = Math`), `Reflect.*`, `Object.getOwnPropertyNames`, `Array#sort` ohne ID-Gleichstand, `Map`/`Set`-Iteration. `hashState` und `cloneState` laufen über eine handgeschriebene Feldfolge; sonst ändert eine Feldumbenennung still den Golden-Hash.
- **Kern-Daten werden injiziert, nicht importiert:** `src/core` importiert keine JSON-Datei. Die Loader (`loadBalance`, `loadLevel`) nehmen `unknown` und werfen mit dem Feldpfad; `src/data/**` liest nur die Schicht darüber (M5). `step()` bekommt Balance, Level und Kollider über `ctx`.
- **Golden-Fixtures sind eingefroren:** `tests/fixtures/core/golden.json` ändert man nur über `npm run core:rebaseline` (druckt alt → neu) **und** eine neue Zeile `Rebaseline: <Grund>` in `docs/decisions.md`; `tests/node/golden-guard.test.ts` bewacht genau diese eine Datei gegen `git show HEAD:…`. `test-balance.json` und `mini-level.json` sind **von Hand** eingefroren und von keinem Wächter erfasst – sie zu ändern ist eine bewusste Entscheidung, und danach verschieben sich die Golden-Zahlen (also re-baselinen und begründen).
- **Texte:** alle sichtbaren Texte in `src/ui/strings.ts`. Ausnahmen – alles Entwickler-Rückkanal, keine Spiel-UI: `<title>` in den HTML-Dateien, das Web-Manifest (`vite.config.ts`), der Diagnose-Text in `src/platform/errorLog.ts`, die technischen `Error.message`-Texte aus `src/net/**` und `src/lab/**` (`ProtocolError`, `CodecError`, `HandshakeError` …), die Zeitleisten-Details (`timeline.push(kind, detail)`) und die Report-Daten des Testlabors (`src/lab/report.ts` mit `reportToText` und den Gründen aus `isRunValid`, `labSession.ts`, `selfTest.ts` mit `DEFAULT_DEVICE`) – sie stehen im Report und werden in der Labor-Oberfläche nur zitiert –, dazu die `Error.message`-Texte aus `src/core/**` (`LevelError`, `BalanceError`, `NaNError`, `RangeError`), die Befundtexte von `validateLevel` und die Fehler der Entwickler-Schichten (`src/render/**`, `src/modes/**`, `src/main.ts`). **Nicht** darunter fallen die Overlay-Bezeichner (`S.debug.*`), der Klapp-Knopf der Hülle (`S.shell.stripCollapse`/`stripExpand`) und die WebGL2-Diagnose (`S.render.webgl2Missing`) – die liest der Nutzer, also stehen sie in `strings.ts`; die Zahlenformate bleiben im Modul.
- **Offline:** keine Fremd-Hosts zur Laufzeit. Kein KTX2/Draco/Meshopt/Basis, keine STUN/TURN-Server, kein Babylon-Legacy-Barrel, kein `@babylonjs/core/pure`, kein `@babylonjs/core/Engines/engine`, kein `import * as` aus Babylon. Die Shader-Chunks werden **lazy** per `import()` geholt und müssen deshalb im Precache stehen – ohne sie ist die Szene offline schwarz. `check-dist` und der Offline-Smoke (mit **Pixelprobe**) sind die Gates.
- **Audio:** genau ein `AudioContext`, nur in `src/audio/audioBus.ts`.
- **`public/spiel/**` ist ein eigenständiger, mitgelieferter Prototyp** (Einzeldatei aus einem claude.ai-Artefakt, three.js): `src/**` importiert daraus **nie** etwas, und `src/main.ts` verlinkt ihn nur (`${BASE_URL}spiel/`). Er ist damit von den Schichtregeln, dem Determinismus und den JS-Budgets ausgenommen – aber **nicht** von der Offline-Regel: keine Fremd-Hosts, alles Fremde liegt in `public/spiel/{vendor,fonts}/` **samt Lizenztext daneben** (MIT ×2, OFL ×2 – die Lizenzen nie von den Dateien trennen). Sichtbare Texte stehen in der Datei selbst, nicht in `src/ui/strings.ts`. Sein eigenes `window.__mb` hat mit dem Test-Haken des Spiels nichts zu tun. Tor: `tests/e2e/proto-offline.spec.ts`; `eslint` fasst die Datei nicht an, `docs/decisions.md` („Prototyp `/spiel/`") hält die geänderten Zeilennummern fest.
- **Testablage:** Vitest findet `tests/**/*.test.ts` (Node-only-Tests, die `git`, `dist`, eine Messuhr **oder eine Datei zum Schreiben** anfassen, liegen in `tests/node` – R15; deshalb liegt `golden.test.ts` dort, nicht nur `golden-guard.test.ts`), Playwright nur `tests/e2e/*.spec.ts`. Endung `.test.ts` vs. `.spec.ts` ist die Trennlinie.
- **E2E-Tor:** **Jeder neue Spec gehört zum Deploy-Tor** (`e2e:smoke`), außer jeder seiner Tests trägt `{ tag: '@local' }` – nur für Tests, die echte Netzwerkschnittstellen, eine persistierte Kamera-Erlaubnis oder die Grafik des Entwicklungsrechners brauchen. Specs, die einen Labor-Lauf (`finishRun`) auslösen, erteilen zusätzlich `local-network-access` (`context.grantPermissions`, additiv); Specs mit echten Kandidaten prüfen Zwischenablage und Report **in der Seite** und lassen nur Wahrheitswerte/Anzahlen heraus (Playwright druckt bei Fehlschlag das geprüfte Objekt). E2E-Specs importieren aus `src/` nur Module, die `src/platform/buildInfo.ts` nicht erreichen.
- **Playwright-Projekte:** drei – `chromium` (alles außer den beiden Fake-Kamera-Specs, per `testIgnore`), `chromium-fakecam` und `chromium-fakecam-foreign` (je ein Spec, je ein eigenes Bild). Jedes Projekt trägt die **volle** Flag-Liste, weil `test.use({ launchOptions })` die Projekt-Argumente komplett ersetzt.
- **Fake-Kamera:** die `.y4m`-Dateien schreibt nur `tests/e2e/globalSetup.ts`, nie `playwright.config.ts` – Playwright löscht `test-results/` **vor** `globalSetup`. Dateimaße = angeforderte Maße, sonst beschneidet und dreht Chromium das Bild und der Smoke wird unbemerkt blind.
- **Tests:** Playwright treibt die Simulation über Ticks (`window.__mb.advance(n)`), nie über Wartezeiten. Golden-Tests laufen gegen eingefrorene Fixtures, nicht gegen die echten Balance-Daten. Playwright-RTC-Tests brauchen eine **persistierte Kamera-Erlaubnis** (`permissions: ['camera']` bzw. `context.grantPermissions`) – das Fake-UI-Flag allein liefert nur mDNS-Namen (siehe `docs/decisions.md`, Tooling-Spike).
- **Nie „fertig" melden ohne frische Ausgabe** der zugehörigen Prüfung. Fehlgeschlagene Prüfungen ehrlich berichten; Tests nicht abschwächen, damit sie grün werden.
- **Geheimnisse:** Das GitHub-Token (`GITHUB_PERSONAL_ACCESS_TOKEN`) nie ausgeben, loggen oder in Dateien schreiben.
- **Datenschutz (öffentliches Repo):** echte Netzwerkadressen (IPs, mDNS-Namen, IPv6-Präfixe) und lokale Benutzerpfade (`C:\Users\<name>`, `/home/<name>`, `/Users/<name>`) aus Tests, Reports, Plänen oder Logs werden nie committet – dokumentiert werden nur Art und Anzahl, Pfade stehen als `$repo = '<Pfad zum lokalen Checkout>'` da. `tests/node/privacy-guard.test.ts` scannt bei jedem `npm test` alle getrackten Textdateien darauf.
- **Unsichtbare Zeichen** (Zero-Width, NBSP …) in Quelltext und Tests nur als `\u`-Escape schreiben, nie wörtlich – der Schreibweg des Agenten hat Escapes schon in echte Zeichen verwandelt. `no-irregular-whitespace` (ESLint-Empfehlung) ist die Rückfalllinie.
- **Werkzeug-Fallen:** Suchen nach unsichtbaren Zeichen über **numerische Codepunkte** schreiben, nie als Escape-Muster (der Schreibweg des Agenten verwandelt Escapes in Dateien in echte Zeichen). Dateien nur über Node schreiben (`fs.readFileSync`/`writeFileSync` mit `'utf8'`), nie über einen PowerShell-Rundlauf. `Select-String -Path 'src\**\*.ts'` ist **kein** rekursiver Glob – der Befehl findet still nichts und sieht dabei grün aus; die Zeilenzahl einer Datei ist `(Get-Content f).Count`, nicht `Measure-Object -Line`. Ein E2E-Spec importiert nie aus einem Modul, das Babylon erreicht: Playwrights ESM-Lader löst dessen erweiterungslose Deep-Importe nicht auf, und `tsc` sieht davon nichts. Belege und Messungen: `docs/decisions.md`.
- **Grenzen des Agenten:** kein Gehör, nur Standbilder → Audio- und Bewegungs-Qualität beurteilt der Nutzer. Bei jeder Test-Bitte an den Nutzer die erwartete Build-ID nennen.

## Testlabor (`lab.html`)
- **Code:** Netz in `src/net/**` (reine Logik: Protokoll, SDP-Codec, Kandidaten, Fehlercodes, Ping-Statistik; Browser-Schichten: `rtcTransport`, `connector`, `environment`, `signaling/textShare`), Labor in `src/lab/**` (`report`, `labSession`, `labUi`, `selfTest`, `labMain`). Definition der Fehlercodes F1–F9: `docs/decisions.md` („M1 – Testlabor I").
- **M2-Module (QR-Pfad):** `qrRender` (Erzeugung), `scannerAdapter` (nativ → Worker), `camera` (Lobby-Stream), `qrPanels` (QR-Block), `pairing` (Paarungsmarken), `lockTest` (Sperrtest), `labEvents` (Seiten-Puffer), `labTypes` (importfreie Typen) und `src/platform/wakeLock`.
- **Reports:** Reports mit echten Adressen bleiben auf dem Gerät (`localStorage`, Schlüssel `maeusebau.lab.reports.v1`). Nach `docs/connectivity-tests.md` kommen nur anonymisierte Reports (`redactReport` bzw. die Knöpfe „… (anonymisiert)"); Roh-SDP wird nie committet. Kandidaten-Ereignisse in der Zeitleiste enthalten nie Adressen.
- **URL-Parameter (nur Entwicklung/Tests):** `?transport=bc&room=<name>&role=host|client&slot=<1–3>` (BroadcastChannel statt WebRTC, zwei Tabs), `?quick=1` (kurze Ping-Serie), `?hook=1` (Test-Haken `window.__mbLab` für Playwright). Details: `docs/decisions.md`.

## Entwickler-Ansicht 2D (`?view=2d`)
- **Kein Spiel-UI, kein Link in der Hülle, kein Text auf der Leinwand** (Schriftrasterung ist der einzige echte Plattformunterschied). Code: `src/render/view2d/{camera2d,draw,loop,hook,main}.ts` (Canvas 2D, kein Babylon), Tastatur als reiner Reducer in `src/input/keyboard.ts` – ohne DOM, ohne Timer, mit `reset()` für den Fokusverlust (`view2d/main.ts` ruft es bei `blur` und `visibilitychange` → `hidden`; ohne Fokus kommt kein `keyup`). `src/main.ts` hängt die Ansicht über einen **dynamischen** `import()` **nach** `mountShell` unter die Hülle.
- **URL-Parameter (nur Entwicklung/Tests):** `?view=2d`, `?clock=manual` (rAF-Schleife wird nie gestartet – gerechnet wird nur über `__mb.advance`), `?layers=rooms,colliders,nav,marks,undershelf,actors` (`all`/leer erlaubt), `?w=`/`?h=` (Vorgabe 960×720), `?seed=` (Vorgabe `1`), `?room=<id>` (Raum-Ausschnitt; unbekannter Name → ganzes Level, kein Fehler).
- **Test-Haken `window.__mb`** wird bei `?view=2d` **immer** installiert (ohne `?hook=1`). Der Vertrag steht in `src/render/view2d/hook.ts` – dort auch, dass `stats().drawMs` die Dauer des **letzten** Bildes ist. `advance(n)` und `setInput(slot, mx, mz, buttons)` werfen `RangeError` bei unbrauchbaren Argumenten (`mx`/`mz` ganzzahlig in [−127, 127], `buttons` in [0, 255] – die Grenzen des Drahtformats), `cmd` hat genau drei Befehle: `benchDraw`, `pixelAt(x, z)` (Welt-Punkt) und `loadFixtures(level, balance)`.
- **Screenshots nur nach `test-results/`** (git-ignoriert): keine Golden-PNGs im Repo, kein `toHaveScreenshot`. Farbproben im Tor-Spec nur in der **Flächenmitte** und mit **± 2 je Kanal**, und nie auf einer Marke (in `feinkost` liegt auf jeder Regalmitte ein Beuteplatz); die exakte Farbtafel prüft ein Vitest-Test. Der Kontext ist `getContext('2d', { alpha: false, willReadFrequently: true })` – das Flag ist für `cmd.pixelAt` (`getImageData`); die ~1,4–1,5 s des ersten Bildes im kalten Chromium sind Rasterizer-Aufwärmkosten, von den Flags **unabhängig** und nicht streng je Prozess.
- **Layout-Korrekturen gehen nur in die Level-JSON**, danach laufen `validateLevel` und die gepinnten Zahlen erneut. Details und Farbtafel: `docs/decisions.md`, Abschnitt „M4 – Core II".

## Graybox 3D (Spielseite)
- **Aufbau:** `src/render/gameMain.ts` ist die einzige Stelle, die alles kennt – Engine (`engine.ts`, WebGL2 **Pflicht**), Szene (`sceneRoot`, `levelMeshes`, `materials`, `actors`), Kamera (`cameraBoom` rein + `cameraRig`), Overlay (`debugOverlay`), Sitzung (`src/modes/{fixedLoop,session,soloSession,hook}.ts`) und der Haken. Ein Kasten je Kollider, ein Boden je Raum, Kapseln für die Figuren; die **Farbe kommt aus der Kollider-Reihenfolge**, nicht aus der Maske. Babylon ist **linkshändig**: `rotationY = -collider.rot` (bewiesen Ecke für Ecke durch die Weltmatrix, Abweichung 7,63 · 10⁻⁷ – ein achsenparalleler Hüllenvergleich ist unter `rot → -rot` invariant und beweist nichts).
- **URL-Parameter (nur Entwicklung/Tests):** `?clock=manual` (rAF-Schleife wird gebaut, nie gestartet – gerechnet wird nur über `__mb.advance`), `?seed=` (Vorgabe `1`), `?tier=low|medium|high` und `?overlay=1` (überschreiben den gespeicherten Wert; der Stufen-Sweep ist am Entwicklungsrechner sonst gar nicht auslösbar, DPR 1,0). `?autostart=1` ist **reserviert und tut nichts** – das Start-Gate ist M6. `?view=2d` schaltet **exklusiv** auf die 2D-Ansicht; die beiden Haken stehen nie zusammen auf einer Seite.
- **Test-Haken `window.__mb`** wird auf der Spielseite **immer** installiert. Der Vertrag steht im importfreien `src/modes/hook.ts`: `advance(n)` rechnet n Ticks und zeichnet **ein** Bild mit `alpha = 1`, `tick()` **liest nur**, dazu `hash()`, `stats()`, `setInput(slot, mx, mz, buttons)` und `cmd` mit genau **fünf** Befehlen – `pose(slot)`, `camera()`, `teleport(slot, x, z)`, `setInput` (dasselbe Funktionsobjekt) und `grid(step)`. `grid` bündelt `scene.render()` und `readPixels` in **einem** Aufruf: ohne `preserveDrawingBuffer` ist der Puffer danach weg (gemessen rgb(0,0,0)).
- **Die Schleife hat einen festen 30-Hz-Schritt** mit injizierter Uhr, 250-ms-Klammer, höchstens 5 Schritten je Bild (Überschuss verworfen und **gezählt**) und einem Kadenz-Teiler `max(1, floor(panelHz / 60))` – `floor`, nicht `round`, sonst wäre 90 Hz gedrosselt. `visibilitychange` hängt an **`document`** (an `window` feuert er nie), `engine.getFps()` wird **nicht** benutzt (es lügt). Die Kamera **schnappt bei jedem Moduswechsel**. `render`/`onFrame` dürfen pausieren: `frame()` prüft danach erneut, sonst laufen zwei rAF-Ketten. `advance(n)` leert den Ereignispuffer bei **jedem** Aufruf, auch bei `n = 0`.
- **Screenshots nur nach `test-results/`** (git-ignoriert): keine Golden-PNGs, kein `toHaveScreenshot`, **kein** Raster-Hash im Tor. Eine Farbprobe vergleicht nie gegen den Tafelwert aus `GRAYBOX_COLORS` – im Bild steht die **beleuchtete** Farbe, geprüft werden auf den hellsten Kanal normierte Verhältnisse. Das E2E-Tor ist mit `tests/e2e/graybox.spec.ts` (drei Tests) auf **17** Tests gewachsen; `--enable-unsafe-swiftshader` ist dafür **tragend**, ohne das Flag rendert die Graybox headless gar nicht. Ein Screenshot **nach** `page.setViewportSize` ist schwarz – je Fenstergröße eine eigene Seite.
- **Der Build-Mismatch-Hinweis der Hülle (`?expect=`) bleibt im eingeklappten Streifen sichtbar** (`shell-note--mismatch`, Ausblendregel mit `:not(…)`) – die Spielseite startet eingeklappt, und ohne die Ausnahme ist der Handy-Loop stumm. Das Tor prüft ihn **auf der Spielseite**.
- **Korrekturen am Bild gehen in `GRAYBOX_COLORS`, in die Licht- und die Boom-Konstanten** – nie in einen Test und nie in eine Schwelle. Details und Messwerte: `docs/decisions.md`, Abschnitt „M5 – Graybox am Desktop".

## Deploy
Nur `push` auf `main` deployt (GitHub Actions → Pages: https://codecrafter-wizard.github.io/mouseraid/).
Build-ID = 8-stelliger Kurz-SHA (`git rev-parse --short=8 HEAD`); `?expect=` und `wait-for-deploy` akzeptieren auch ein ≥ 7-stelliges Präfix. Dirty-Builds heißen `<sha>-dirty-<HHmmss>` (UTC) und werden nur exakt verglichen.
`node scripts/wait-for-deploy.mjs <sha>` wartet, bis die Build-ID live ist. Pages liefert mit `max-age=600` aus → am Handy „Nach Update suchen".
